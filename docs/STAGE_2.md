# Этап 2: файловое и криптографическое ядро

## Реализация

`next/internal/workspace` не зависит от окна: сканирование, метаданные, валидация путей, CRUD, preview корзины и передача реальной операции удаления desktop-адаптеру. Сканирование не следует symlink; операции отклоняют разрешённый через symlink путь за пределами корня. Пути вкладок остаются относительными к неизменяемому workspace.

Сохранение использует временный файл в той же папке, сохранение прав, fsync и rename. Ожидаемая ревизия включает timestamp и SHA-256 содержимого; она проверяется до записи и перед заменой. Это замечает внешнюю запись с сохранённым mtime. Как в исходной версии, отдельная проверка и rename не являются межпроцессной транзакцией: другой редактор теоретически может записать файл между ними.

Watcher на fsnotify следит за вложенными каталогами, добавляет новые каталоги, исключает скрытые/служебные пути, объединяет события за 100 мс с пределом задержки 500 мс. `Close` дожидается остановки goroutine и закрытия каналов. Подключение watcher к вкладкам и смене корня выполняется на этапе интерфейса.

Прототип уже открывает и сохраняет файлы через это ядро вместо временной файловой реализации этапа 1.

`next/internal/cryptoblock` реализует immutable `enc:v1`: Argon2id + XChaCha20-Poly1305, те же параметры, AAD, Base64URL и UTF-8. Пароли и plaintext не сохраняются. Очистка принадлежащих пакету буферов не означает гарантированную очистку всех копий строк Go.

## Проверки

- Портированы существенные сценарии Rust-тестов: заголовки/названия, CRUD без перезаписи, исключения, пустые папки, защита путей/symlink, корзина, права, большой файл, быстрые ревизии, устаревшая ревизия и принудительное сохранение.
- Настоящие файловые события: изменение вложенного файла, создание каталога, изменение файла в новом каталоге, остановка и закрытие каналов watcher.
- Go генерирует тот же фиксированный payload, что Rust `V1_FIXTURE`; неверный пароль, повреждение и неизвестная версия отклоняются.
- `python3 next/scripts/crypto_compat.py` создаёт временный Rust harness из неизменённого исходного `crypto.rs` (убираются только атрибуты Tauri). Прошли все 3 исходных Rust-криптотеста и обмен случайными блоками с Unicode в обе стороны: Go → Rust и Rust → Go.

Полные проверки и smoke GUI выполняются перед коммитом. Полная Tauri-сборка для криптографической проверки не нужна: harness компилирует исходную реализацию отдельно.
