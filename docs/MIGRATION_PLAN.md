# План переноса Plainmark на Go + MyGo

Дата: 3 ноября 2026 года. Статус: выполняется. Каждый этап завершается отдельным коммитом; если этап требует нескольких частей, промежуточные коммиты явно называют часть. Незавершённые проверки остаются открытыми.

## Цель и границы

Создать настольное приложение на Go с собственным UI MyGo. Сохранить пользовательские сценарии текущего Plainmark и совместимость заметок. Пиксельное совпадение, прежняя CSS-вёрстка и внутренний Tauri IPC не требуются.

Первой целевой платформой принять macOS, поскольку текущая упаковка настроена на `.app`. Необходимость выпуска под Windows/Linux уточнить перед работами по дистрибуции.

Исходную реализацию сохранить в корне репозитория; новую разрабатывать независимо в `next/`. Не удалять старую версию до проверки функционального соответствия. Обе версии работают с обычными папками заметок без конвертации Markdown в собственную базу данных.

| Просмотр | GFM, таблицы, математика, скрытие метаданных, ссылки и якоря | Использовать `ui/markdown` с адаптерами Plainmark |
| Режимы | Просмотр, редактирование, split; подсветка блока по строке | Сохранить функции, допустима другая компоновка |

| Шифрование | Выделение → fenced-блок `encrypted`, временное раскрытие | Полная совместимость `enc:v1` |

## Архитектура новой версии

Планируемая структура:

```text
next/
  cmd/plainmark/           # запуск приложения
  internal/workspace/     # сканирование, пути, файловые операции, сохранение
  internal/session/       # вкладки, черновики, конфликты, команды
  internal/cryptoblock/   # совместимый enc:v1
  internal/preview/       # Markdown, ссылки, метаданные, encrypted-блоки
  internal/mathrender/    # адаптер формул и кеш
  internal/settings/      # собственные настройки и состояние новой версии
  internal/desktop/       # MyGo: окно, меню, диалоги, watcher, clipboard
  internal/ui/            # дерево, вкладки, редактор, просмотр, настройки
  locales/                # словари интерфейса
  go.mod
  go.sum
```

Файловую и криптографическую логику отделить от UI. Дисковые операции, сканирование и KDF выполнять вне отрисовки; результаты применять через механизм обновления окна MyGo. Устаревший результат после смены workspace не должен менять новую сессию.

## Markdown и формулы

MyGo предоставляет готовый Markdown UI с CommonMark/GFM. В изученной версии API математическая вёрстка подключается через `Options.Math` и `Options.InlineMath`; без обработчиков показывается исходный TeX.

Кандидаты для короткого сравнительного прототипа:

1. `github.com/go-tex/math`: чистый Go, SVG из контуров символов, встроенный STIX Two Math.
2. `github.com/luo-studio/go-tex`: Go-порт RaTeX, ориентированный на KaTeX, готовый PNG-вывод и встроенные шрифты.

Это кандидаты, а не подтверждённые зависимости. Выбрать по реальным формулам Plainmark: дроби, индексы, интегралы, матрицы, `cases`, многострочные выражения, ошибочный ввод, inline baseline, масштабирование и темы. Заявления о совместимости библиотек не заменяют эту проверку.

Для inline-формул адаптер должен возвращать ширину, высоту над baseline и глубину под ней. Для блочных — учитывать доступную ширину. Кешировать по TeX, размеру, стилю display/inline и цвету; ограничить кеш. Если SVG несовместим с загрузчиком MyGo, проверить растровый путь при корректном HiDPI-масштабе.

## Неизменяемый контракт enc:v1

Источник истины: `src-tauri/src/crypto.rs` и `V1_FIXTURE` в его тестах.

- Argon2id, версия 0x13: память 65536 KiB, 3 прохода, параллелизм 4, ключ 32 байта.
- XChaCha20-Poly1305, salt 16 байт, nonce 24 байта.
- AAD: `plainmark:encrypted-block:v1`.
- Формат: `enc:v1:<salt>:<nonce>:<ciphertext-with-tag>`, Base64 URL-safe без padding.
- Пароль и текст кодируются UTF-8; неизвестные версии отклоняются.

Изменение алгоритма требует нового формата, а не изменения v1. Учесть отличия управления чувствительной памятью в Go и Rust; не обещать эквивалент `zeroize` для Go-строк.

## Проверка результата

Исходная проверка от 3 ноября 2026 года: после восстановления скопированной `node_modules` командой `npm ci` прошли `npm test` (10 файлов, 66 тестов) и `npm run build` (TypeScript + Vite). Сборка предупреждает о размере JS chunk. `npm ci` сообщает о 8 уязвимостях зависимостей; обновления пакетов в рамках фиксации исходной версии не выполнялись. Rust-тесты, сборка Tauri и запуск GUI в этой проверке не выполнялись.

Основные автоматические проверки: файловые операции в временных папках, сохранение/конфликты, криптографическая совместимость, переходы состояния вкладок. Существующие TS/Rust-тесты использовать как описание поведения, переносить существенные сценарии.

Ручная приёмка: открыть старую папку, изменить несколько вкладок, переименовать/переместить папку, изменить и удалить файл извне, разрешить конфликт, расшифровать старый блок, проверить формулы и перезапустить приложение.

Оценка до прототипа: 2–4 рабочих дня на этап 1, ориентировочно 4–7 недель одного разработчика на полный перенос под macOS. Это предварительная оценка, не подтверждённый срок; уточнить после этапа 1.
